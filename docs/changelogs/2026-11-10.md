## Decisions

- **One Pico 2 carries the IMU and the ToF sensors** (2026-11-10). It keeps the name `/dev/imu`
  (the Pi's udev rule matches its serial number), so the Pi's rules don't change for it.
- **`tof_node` reads both Pico programs**: Noel's `src/pico2/main.py` (binary packets: IMU at
  100 Hz with acceleration, plus ToF) and Ling's `src/imu/stream_main.py` (`I,...` text lines, IMU
  only, what's on the robot's Pico now). The robot keeps its heading whichever is loaded, so loading
  Noel's code later needs no switch anywhere.
- `/imu/data` from `tof_node` matches what `imu_bridge` sent (frame `imu_link`, same variances,
  stamped on arrival), so the EKF settings don't change. `imu_bridge` stays in the repo for
  checking the IMU by hand, but nothing starts it.
- **Wake both lines.** The new cable has BRC on RTS (Noel tested it); the old one used DTR, if
  wired at all. Pulsing both together works with either cable, so the change no longer has to
  wait for the new cable to be installed, as Noel's commit note said.
- "ToF safety stop" is **off by default**: with it on and the sensors not sending, forward driving
  is blocked (missing data counts as danger, by design).

### Noel's firmware, `src/pico2/main.py`
- The IMU is looked for at 0x4A and 0x4B. The robot's IMU answers at 0x4A (Ling's wiring,
  `docs/setup/ros2-pi.md`); Noel's board at 0x4B. Before, it only tried 0x4B, so on the robot it
  would have streamed without the IMU.
- Without the ToF sensors (not wired yet, or one not answering), it now logs why and streams the
  IMU alone. Before, a missing sensor stopped the program, IMU included. Safe for the stop: the Pi
